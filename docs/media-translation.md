# Images, captions and live speech

The image reader includes English, Simplified Chinese and Japanese models in the installation. The OCR language picker also offers 124 official Tesseract language models; a selected additional model downloads once and is cached in the extension profile for offline reuse. The download is data, never executable JavaScript or WebAssembly. The manifest pins the official `tessdata_fast` repository to commit `87416418657359cb625c412a48b6e1d6d41c29bd`, including each file's size and Git object digest, and verifies the bytes before initialization. The model data is Apache-2.0.

Image and scanned-PDF OCR language selectors share a persisted preference, including mixed-language combinations, and remain synchronized after reload.

OCR jobs run serially in a bundled local Tesseract worker. Tesseract.js 7.0.0 contains an object-language initialization typo: its loader uses `.code` and `.data` but its initializer joins `.data` as the language name. The build applies a narrowly checked correction to use `.code`; it fails if the expected upstream code changes. No remote worker scripts are loaded. Bundled model loading and additional French model initialization/offline reuse have browser acceptance coverage.

Image translation masks glyph pixels inside recognized text lines and reconstructs their backgrounds with local harmonic interpolation. A two-pixel fringe includes antialiasing that OCR boxes can omit; pixels outside those regions remain intact. Line bounds prevent incomplete CJK word boxes from leaving substantial original strokes behind. Text placement fits the recognized region, respects right-to-left direction, and wraps grapheme clusters without breaking combining marks. This removes the previous unconditional white rectangles. It is not a trained image-restoration model: complex textures, lettering over detailed illustrations, recognition errors and undersized regions still require review. It cannot reproduce arbitrary artistic lettering or guarantee the original service's image quality.

Website subtitles are read from native HTML video/audio text tracks, common player DOM caption containers, and open shadow roots. New tracks and roots are discovered during playback. Disabled native tracks can be enabled in hidden mode while translating and their previous mode is restored when translation stops. Supplied SRT, VTT and ASS/SSA sidecars can be attached as native cues with their original times. The bilingual overlay follows fullscreen changes and supports right-to-left text. Closed shadow roots, private player APIs and encrypted caption streams cannot be inspected through ordinary DOM access.

Screen subtitle capture is an explicit fallback: the user selects a browser tab or screen, local OCR reads the selected region every two seconds (the lower 30% by default), and only changed recognized text goes to the configured translation provider. It runs one OCR/translation job at a time. Protected video may appear black because the browser restricts capture; the extension does not bypass that restriction. Capture stops and releases tracks when the user stops sharing.

Live microphone/tab audio now uses an AudioWorklet and independently encoded 16-kHz mono PCM WAV segments. The default segment is three seconds, configurable from two to five seconds. Voice activity detection finishes a segment after approximately 500 ms of silence and avoids uploading idle silence. Each timestamp derives from captured sample counts. The queue is limited to four segments and capture stops rather than silently dropping audio when processing falls behind. A PCM ScriptProcessor fallback is available where AudioWorklet is unavailable. Stop finishes queued transcription; cancellation discards queued results.

The speech endpoint is OpenAI-compatible `/v1/audio/transcriptions`. A separately configured hosted or local endpoint takes precedence. With the local bridge selected and speech URL empty, the extension derives the bridge's `/v1/audio/transcriptions` route and preserves its authentication token. The bridge can run an optional local whisper.cpp model. AGY remains the translation engine; speech recognition runs separately. Short chunks reduce capture latency, but endpoint latency and short-utterance recognition quality still affect the result. This is chunked transcription, not a streaming token/audio protocol.

Primary references: [Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md), [official fast OCR models](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd), [AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet), [TextTrack cues](https://developer.mozilla.org/en-US/docs/Web/API/TextTrack/cues).

## Select a screen subtitle region

The live workspace offers bottom, top and full-screen OCR presets. Drag a rectangle on the shared-video preview to select a custom region. The selection persists in this browser profile. Letterboxed previews map dragging to the visible decoded video instead of the surrounding bars. Region coordinates are normalized to the captured frame (`left`, `top`, `width`, `height` between zero and one), so the selection continues to work when the preview resizes. Changing regions drops stale results from the previous region. Presets and drag selection have browser acceptance coverage with distinct upper/lower caption fixtures.

Chinese/Japanese OCR removes artificial ASCII separators between recognized CJK glyphs while preserving Latin word boundaries, Korean spacing and line breaks.

Native captions now use hidden native tracks while the extension's bilingual overlay is active, preventing a second copy of the browser's source subtitles. Switching the selected track retires the previous track; stopping restores the selected track's previous mode, while preserving a user mode change made during translation. A cleared caption explicitly hides its overlay, including the shadow host's CSS display state.

## Paired original media evidence

Run `node scripts/reference-media.mjs /private/path/to/original-extension` after a fresh build. The harness requires the pinned original 1.33.3 content hash and validates the replacement build's source/bundle evidence. It runs original and replacement in separate profiles against the same local translation endpoint and controlled native VTT / generic DOM caption fixtures. REA captures passive page evidence and screenshots under ignored `dist/parity/media`; the sanitized case report is `dist/parity/media-results.json`.

The fixture supplies explicit original adapter configuration to enable native/DOM captions on localhost; this does not establish that arbitrary production sites use the same rule. The harness records source/target text, changing cues, gaps, original cue times, native-track visibility, stop behavior and fullscreen containment. Differences remain visible in the report; a runnable original that behaves differently is not reported as a successful match. The reference's short-caption language heuristics can skip strings that a complete English sentence causes it to translate. A successful local fixture does not establish commercial video-service access, DRM capture, all 124 OCR models' accuracy, image-restoration quality or live-meeting transcription quality.

The 2026-10-12 bound media run records seven matches, two differences and one unresolved reference case. Native source/target text, cue changes, gaps, cue times, hidden native tracks and fullscreen containment matched on an original silent VP8 video fixture. The original DOM adapter translated the first caption, but repeated the English source on the changed-caption probe; that case does not count as a match. The stop probes compare the original temporary-disable message against the replacement toggle: the original leaves the native track hidden and leaves the DOM translation visible, while the replacement restores the native track and clears its overlay. These differences remain in the published report. The evidence establishes semantic behavior for this fixture, not pixel equality or a latency bound.
